# CP05 implementation — work in progress

CP05 is **not complete**. The only functional change so far corrects the North and South America configuration to point to the existing underscore-named SVG files. Their embedded amCharts copyright notices are retained. The existing provenance audit identifies unresolved version, license and attribution questions; these remain public-launch blockers. Representative geometry was checked in an automated file test; this does not prove every target works or that the boundaries are accurate.

## Existing architecture and investigation

`applyMap` assigns the selected key, region pool and `<object>.data`. The object's single load handler retrieves `contentDocument`, styles it, adds hover handlers and may attach the locate listener. Locate listeners capture the current session and document; navigation removes the bound listener. `getRegionName` translates SVG attributes through a shared alias table. Question selection uses the configured region list, not a validated list of available geometry. Map zoom is a CSS transform on the wrapper with wheel and pointer/touch handlers; it lacks accessible controls. `gameState` remains the only mutable gameplay session.

The two Americas paths contained spaces, while the checked-in filenames contain underscores. The file test reproduced this mismatch before the correction. A development browser smoke test reproduced the I-15 symptom: World Edition retained the India SVG document beyond its five-second assertion window. This does not establish the cause. A plausible lifecycle hazard is that the shared object load handler does not verify the loaded document URL against the current selection; this is a hypothesis, not an established cause. The current implementation has no comprehensive mapping validation or loading error recovery.

Remaining CP05 work includes deterministic request ownership and cleanup, validated geometry and question pools, equivalent keyboard interaction, accessible viewport controls, responsive/touch and race testing, performance measurements and full licensing investigation. Do not accept CP05 on the basis of the filename fix.

## Corrective pass: ownership and preliminary eligibility

Each new selection now replaces the object element instead of assigning a new URL to the previous object. The active element and a monotonically increasing generation own the load handler. A callback accepts an SVG only when element, generation and resolved document URL match; replacement detaches the locate listener. This is a mitigation for stale ownership, not a proven diagnosis of the original intermittent Chromium behavior. An instrumented test delaying an already-started India request passed even before the change, so that particular race did not reproduce the original failure. The initial map can be deferred while its game screen is hidden.

Locate setup now derives its question pool from configured names that occur as path labels under the existing alias rules. Duplicate configured names are excluded and unrepresented names are listed to the player. Wrong clicks outside that pool are ignored, and the challenge timer starts when locate setup has a nonempty pool. The progress and win counts use this pool. This prevents questions for names absent from the observed path labels, but a name match alone does not validate geometry, country identity, duplicate SVG identifiers, hit size, political boundaries or physical interaction. The source alias rules remain insufficiently audited. Mode-specific geographic validation and a complete supported-target policy remain open.

`tools/audit-map-labels.py` inventories the current labels and reports multiple paths separately: they can represent fragments rather than duplicates. On this pass it reported missing labels for Xizang (Tibet), Cape Verde, Republic of Congo, Swaziland, Armenia, Azerbaijan, Cyprus, Georgia, Turkey and Federated States of Micronesia. Some are naming/alias conflicts, not established absence of geometry. No territory or disputed boundary policy has been settled and no geometry was invented.

This corrective pass does not implement the required accessible controls, non-pointer selection, verified touch gestures or performance measurement. The asset provenance and licensing blockers remain as documented in `docs/audit/ASSET_PROVENANCE.md`. CP05 is incomplete and must not be accepted.

The label inventory also found repeated XML IDs in multiple country assets. For example, India reuses `INAN` on a path and a circle. These may be source-asset marker pairs, but they have not been reviewed exhaustively. The runtime label filter does not disambiguate these IDs, so duplicate-ID and ambiguity validation remains an acceptance blocker.

## Final-pass geographic inventory and blocker

`python3 tools/inventory-map-geometry.py` writes `docs/engineering/CP05_MAP_INVENTORY.json`. It records the SHA-256 of each configured SVG and of each path's `d` attribute, every path's document and path index, available identifiers and labels, missing path IDs, duplicate IDs across all element types, and the configured region list. The stable indices refer only to the asset bytes identified by the corresponding hash. This is a mechanical inventory, **not a canonical target registry**. All identities, regional membership, absent entities and non-geographic classification remain unverified. The report intentionally does not infer absent countries or supported geometry from a label match. No target has been validated to the standard requested for I-12; the current runtime still permits label-matched targets, so it does not enforce that standard.

All 1,347 paths in the 32 configured SVGs have an ID. In each of 16 country SVGs, every duplicate ID observed is shared by one path and one circle (for example `INAN` in India). This establishes the element types, not that the circle is legitimate answer geometry or that the path depicts the named entity. The other 16 assets have no repeated IDs. Australia's multiple matching paths require separate fragment validation; repeated labels do not prove they depict the same entity. The Asia SVG contains a path labelled American Samoa (`AS`), which is not in the configured Asia question list; this shows the file includes at least one candidate outside the configured region, though its actual geometry still requires validation. The prior label audit's ten unmatched configured names remain candidates for absence or naming mismatches, not confirmed absent polygons.

A possible replacement is [Natural Earth](https://www.naturalearthdata.com/), which publishes public-domain Admin 0 and Admin 1 data, with [versioned cultural downloads](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/) and a stated de facto boundary policy and optional points of view. [geoBoundaries](https://www.geoboundaries.org/api.html) provides source and license metadata for individual administrative layers and describes its gbOpen release as CC BY 4.0 compatible. Neither has been downloaded, matched against the full question set, reviewed for point-of-view and subdivisions, converted, or tested for small-target hitability. Neither is established as a drop-in replacement. In particular, a boundary and entity policy and version-pinned, reviewed source data are needed before a defensible registry can be constructed. Existing asset licensing remains a launch blocker; no rights have been inferred from metadata alone.

The present work stops at this evidence-backed identity/provenance blocker. Accessible answer selection, viewport controls, physical touch evidence and the requested deterministic mutation test are not implemented in this pass. Existing generation, document and session guards remain intact. Do not interpret prior green browser tests or this inventory as CP05 acceptance.

## Geographic foundation recovery

The source compatibility gate failed; no gameplay code or map asset was replaced in this pass. See `CP05_GEOGRAPHIC_RECOVERY.md`, `CP05_GEO_REQUIREMENTS.json`, and `CP05_GEO_FEASIBILITY.json` for the 32-scope, 1,174-question snapshot, eight India bonuses, version-pinned source checksums, topology findings and per-question candidate lists. Question keys are not canonical geographic identities and zero candidate mappings have been independently validated. Natural Earth 1:110m lacks a discovery candidate for 29 world labels; 10m Admin-1 uses departments for France and provinces for Italy, incompatible with direct replacement of the game's region questions. Name equality also produces multiple distinct source candidates for Washington, Buenos Aires and México. These are concrete reasons not to use arbitrary name matches or silently replace assets. The India gbOpen sample has 36 features but its stated represented year and apparent post-2011 entity names require source reconciliation. No advertised gameplay coverage was intentionally changed in this pass.

The strongest evaluated path is a reviewed 1:50m or 1:10m Natural Earth Admin-0 world registry plus separately validated subdivision sources or carefully reviewed aggregations, retaining the existing assets until coverage, policy, licensing and interaction are established. Accessible selection, viewport controls and deterministic I-15 guard tests remain open because the requested sequence gates them on the geographic foundation.

## Controlled geographic reconciliation

`CP05_GEO_REGISTRY.json` is a versioned, non-runtime reconciliation ledger preserving all 1,182 question and bonus occurrences. It contains 196 country-code groups, 36 India candidate source pairs and 757 unverified other subdivision records. Country grouping uses game-side codes and source identifiers plus GEOS and cross-scale geometry checks; 167 country records are technically reconciled, not independently verified or approved for gameplay. Seven world country shapes remain ambiguous under the cross-scale check, 22 country records require policy review and all 36 India pairs require source-date/boundary review. The 757 other subdivision question records require independent administrative verification; 611 have a single source candidate corroborated by an untrusted legacy SVG ID. The ledger has 989 records, but an exact number of distinct geographic entities is not established because the unresolved entries are provisional. `CP05_GEOGRAPHIC_RECONCILIATION.md` documents methods, source IDs, caveats, evidence and pilot blockers.

No world pilot was integrated: the 50m and 10m Vatican polygons do not overlap and small island states differ materially in represented pieces; the game has no verified small-target or policy solution. Existing maps and scoring/session code remain intact. `tools/validate-geo-registry.cjs` and its targeted tests check ledger consistency; structural validation does not establish geographic correctness. CP05 remains unaccepted.

## Isolated development world pilot

A non-production pilot lives in `pilot/` and is not a live mode or a replacement for `svg/world.svg`. The fixture contains eight source-identified countries from Natural Earth 10m 5.1.1, with 623 polygon pieces and a manifest listing all 186 excluded world questions. ISO identities and source feature IDs were checked against UN M49 and independent GeoNames anchor positions; valid source and simplified/rounded geometries and anchor containment were checked at generation time. Fiji was excluded after its Suva anchor failed containment. This limited check is not a certification of complete boundary accuracy. The fixture implements pointer/keyboard/chooser scoring, focus, status feedback, 1×–5× zoom, directional and drag pan, reset and touch tap. Generation ownership and listener cleanup guard replacement; a deliberately disabled owner guard demonstrates the stale-load failure. See `CP05_WORLD_PILOT.md` for provenance, reproduction, coverage and limitations. The live game's target mapping and CP05 acceptance remain open.

## Full-world development continuation (2026-11-01)

The eight-country pilot remains development-only. Its generation guards and interaction tests are useful evidence for an eventual adapter, but its independent session and development harness must not replace the authoritative CP04 game session. The live world and regional maps were not migrated. `CP05_WORLD_COVERAGE.json` records all 194 configured questions and `candidate/world-manifest.json` records the isolated diagnostic SVG; neither grants live approval. The candidate groups each source feature under its canonical ISO-style ID, independently of its boundary representation. This allows future alternative views without changing game identity, but alternative views are not implemented.

The user selected Natural Earth's default de facto view as a provisional development baseline, not a sovereignty determination or automatic approval of disputed features. Indian mapping requirements and other applicable distribution rules must be verified before release. Source code correlations are not sufficient to clear identity, boundary, reachability or interaction gates. Consequently no new game adapter or candidate gameplay has been activated.

Generate the diagnostic candidate after producing the coverage report with `PYTHONPATH=/tmp/mapmaster-geodata/python python3 tools/audit-world-coverage.py` and `PYTHONPATH=/tmp/mapmaster-geodata/python python3 tools/generate-world-candidate.py`; these offline tools require existing pyshp, Shapely/GEOS and NumPy installations and the pinned archives/reference inputs described by the scripts. The generator verifies the 10m archive checksum, preserves all game question identities, validates its rounded polygons, runs a planar overlap scan, and records all other Natural Earth features as noninteractive context. Regenerating the audit alone resets candidate status until the candidate generator is rerun. Neither tool is a runtime dependency.

## Full-world candidate interaction harness (2026-11-01)

`pilot/world/` is an isolated validation harness; it loads the existing diagnostic SVG and versioned manifest without changing either or the live map. `pilot/candidate-core.mjs` adapts manifest identities and rejects duplicate or malformed IDs. The harness checks target IDs and polygon counts before installation, then reuses the eight-country pilot's exact-ID scoring, view clamps and generation ownership. It offers mouse/touch, keyboard and chooser selection, bounded controls, focus, reset, review and a new-session transition. Shape names are generic during the quiz; chooser options contain country names. Runtime listeners are aborted on replacement and page hide, and stale responses are checked before installation. The geographic coverage gate remains closed; see `CP05_WORLD_CANDIDATE_VALIDATION.md`.

## Release-gate adapter preparation (2026-11-01)

`js/world-map-adapter.mjs` is an inactive adapter seam for a later reviewed integration. It validates one unique canonical ID and DOM ID per manifest entity, requires exact one-to-one candidate/question coverage, and receives the authoritative CP04 session through a callback. An event can emit a country only when the active SVG document, captured session and current authoritative session all agree. Pointer-down identity is retained through pointer capture; movement over six pixels suppresses scoring; keyboard/assistive click paths use the same identity validation. The adapter does not own game state and is not imported by live game scripts, so it cannot change scoring, lives, timer, review, navigation or World/India switching today.

The release-gate tests cover wrong DOM IDs, stale sessions, retired documents, pointer capture and drags. The isolated candidate provides the actual development-only mouse, keyboard, chooser, touch-emulated, focus, pan/zoom/reset and stale-response evidence. It is still excluded from `dist`, and no candidate activation was made because geographic, policy, accessibility and performance gates remain unresolved. This work does not prove the original I-15 root cause.

## Controlled CP04 candidate integration recovery (2026-11-01)

The 194-country candidate is mounted only on `http://127.0.0.1:4174/?cp05Candidate=1`. `events.js` inserts its module script at runtime rather than using a dynamic import in a classic script; this preserves the required nine-script classic order and avoids Vite rewriting `events.js` into module syntax. The bridge is unavailable on preview, production and `/mapmaster/`, while the build-copy allowlist excludes candidate and pilot assets plus their modules.

The bridge resolves only manifest-backed canonical identities and passes the result to CP04's `applyLocateSelection`. CP04 remains the sole mutable owner of score, attempts, streak, lives, deadlines, timer cleanup, terminal states, review and restart. Adapter document/session checks, classic-map generation ownership and CP04's `canPlay()` guard prevent stale, terminal or review-state input from mutating a current session. SVG `<g>` targets dispatch a bubbling click for Enter/Space because browser groups cannot reliably be invoked through `.click()`.

During CP04 review, the development candidate remounts only as a read-only map/chooser surface. Pointer pan and selection remain active-session-only; keyboard and chooser events route to CP04 and are rejected by its review guard. Leaving review, restarting, navigating away or replacing a map disposes the candidate and its listeners. The browser regression uses Albania as the eligible wrong answer while Afghanistan is the target; a non-eligible country is correctly ignored and cannot be counted as an incorrect gameplay answer.

This is controlled development integration, not public activation. Geographic feature approval, disputed/context treatment, source/licensing review, physical-device and assistive-technology testing, and sustained rendering/memory measurement remain release blockers.

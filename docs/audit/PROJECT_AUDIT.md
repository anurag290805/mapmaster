## Technology and ownership

Static `index.html`, five custom stylesheets, ordered classic scripts, SVG `<object>`, embedded WAV/Web Audio, browser localStorage, Google Fonts and Twemoji CDN. No build or installed project dependency. Serve from the project root with `python3 -m http.server 8080` (same origin required for SVG document access); local `file:` behavior varies by browser. `data.js` owns maps and geography; `state.js` shared mutable state; `ui.js` DOM, map translation and rendering; `modes.js` answers; `game.js` lifecycle; `events.js` bindings and navigation; `audio.js` sound. `Readme.txt` is stale about layout, filenames, map count and opening directly. Screenshots are historical assets, not current test evidence.

## Assessment

Retain the low-cost static architecture and assets provisionally; isolate pure answer and session logic, version data and save schema, and incrementally refactor map adapters and UI. A framework migration has no demonstrated benefit. Existing JavaScript parses and SVGs are well-formed XML, but that is neither gameplay nor visual validation. Critical issues include false-positive/repeated typing, two broken map URLs, partial geography pools and no proven keyboard map alternative. There is no evidence of a framework, backend, account, saved game, analytics, service worker or offline asset cache. The only observed persistent key is `mapmaster-theme` (`dark` or `light`); sound and gameplay are memory-only. Never clear it during migration.
